# M7 polish checks

This sheet maps public README and docs claims to committed benchmark records, and lists the commands to reproduce them. tok/s means tokens per second. pp is prompt processing; tg is generation after the first sampled token.

M7 supplies the rewritten README, a model/quant speed comparison, a real
terminal GIF, a design post and a docs hub. The roadmap acceptance wording is
unchanged. No tag or release is created.

R1 later updates the Q4_K_M README row and the shared speed chart. The
original M7 validation and artifact hashes below describe the M7 snapshot.

## Speed table

[The derived comparison](reference/m7-benchmarks.json) is generated by
`python3 bench/m7_table.py`. It computes rates from saved counts and times,
checks matching model hashes and prompt IDs, and links every source file.
The README rounds to two decimal places. It does not use the M6 TinyStories
regression timings, which were collected during other activity.

| Rows | Neuron record | llama.cpp record | Protocol |
| --- | --- | --- | --- |
| TinyStories 15M F32 | `tinystories-m5.json` | `tinystories-15m.json` | M1 prompt set, context 2048, 128 output tokens, three repetitions |
| SmolLM2 135M Instruct F16 | `m7-speed-smollm-neuron.json` | `m7-speed-smollm-llama.json` | Short M7 pair |
| Qwen2.5 1.5B Instruct F16 | `m7-speed-f16-neuron.json` | `m7-speed-f16-llama.json` | Short M7 pair |
| Qwen2.5 1.5B Instruct Q8_0 | `m7-speed-q8_0-neuron.json` | `m7-speed-q8_0-llama.json` | Short M7 pair |
| Qwen2.5 1.5B Instruct Q4_0 | `m7-speed-q4_0-neuron.json` | `m7-speed-q4_0-llama.json` | Short M7 pair |
| Qwen2.5 1.5B Instruct Q4_K_M | `r1-speed-final.json` | `r1-speed-llama-final.json` | R1 repeat of the short M5 pair |

All files in that table live in `bench/reference/`. Every row uses four
threads in each engine. Neuron uses automatic AVX-512 for TinyStories and
explicit AVX-512 for short samples. llama.cpp uses its native CPU-only
build pinned at `9e9619d030bbe6b584d826a0a6cf06e38251f52b`. The TinyStories
pair has one llama.cpp warmup per thread setting and no separate Neuron
warmup. It pools nine samples from three prompts. It is a historical
comparison, not a controlled contemporaneous experiment.

A short pair uses the raw prompt `Once upon a time`, context 256, greedy
decoding, 32 generated tokens, one repetition and no warmup. Neuron and
llama.cpp receive the same prompt IDs. llama.cpp disables prompt caching
and uses seed 42, temperature zero and repetition penalty one. Its batch
and generation thread counts agree. The harness records commands, hashes,
output IDs, timings and machine state for each sample.

Prompt speed is `1000 * sum(prompt_n) / sum(prompt_ms)`. Generation speed
is `1000 * sum(predicted_n - 1) / sum(predicted_ms)`: the first sampled
token is produced by prompt evaluation. Loading is excluded. Neuron
processes prompt tokens sequentially; llama.cpp can batch them. The short
prompt does not characterize long-prompt throughput. Outputs between
engines need not be identical; the timing table is not a quality check.

Hardware: an Intel Core i5-1135G7 laptop (4 cores/8 threads, AVX-512 VNNI),
16 GB RAM, AVX2 and AVX-512 with VNNI, Ubuntu 22.04 base, GCC 11.4.0,
CMake 3.22.1. M7 measurements ran sequentially with no simultaneous builds,
tests or other model runs. Other development tools, documentation work and
normal services were present. AC was connected, the battery full, the `powersave` governor and
`intel_pstate` driver active, and turbo enabled. Frequency and temperature
were not fixed. Before/after observations are in each raw JSON; background
load and thermal variation limit comparisons across collection times.
[The M1 method](BASELINE.md) and [M5 method](SPEED.md) describe older rows.

## Reproduce

From the repo root, keep models and the reference engine outside the clone,
then prepare the pinned files:

```sh
export NEURON_MODELS_DIR="$HOME/.cache/neuron/models"
export NEURON_LLAMACPP_DIR="$HOME/.cache/neuron/llama.cpp"
scripts/fetch_models.sh
scripts/build_llamacpp.sh
cmake --build "$NEURON_LLAMACPP_DIR/build" --target llama-quantize -j 2
for type in Q8_0 Q4_0; do
  "$NEURON_LLAMACPP_DIR/build/bin/llama-quantize" --pure \
    "$NEURON_MODELS_DIR/Qwen2.5-1.5B-Instruct-f16.gguf" \
    "$NEURON_MODELS_DIR/Qwen2.5-1.5B-Instruct-$type.gguf" "$type" 2
done
"$NEURON_LLAMACPP_DIR/build/bin/llama-quantize" \
  "$NEURON_MODELS_DIR/Qwen2.5-1.5B-Instruct-f16.gguf" \
  "$NEURON_MODELS_DIR/Qwen2.5-1.5B-Instruct-Q4_K_M.gguf" Q4_K_M 2
cmake -S . -B build -DCMAKE_CXX_COMPILER=g++
cmake --build build -j 2
ctest --test-dir build --output-on-failure
```

The Q8_0 and Q4_0 table rows use the pure files, not the historical
F16-embedding probe files. Q4_K_M uses the standard mixed preset.
[QUANT.md](QUANT.md) preserves hashes and original production commands.
No quantization or long quality benchmark was rerun for M7. Running
`fetch_models.sh` against the existing external directory verified all
three pinned downloads without changing the weights.

Repeat short pairs with the existing speed harness. The default model is
Qwen Q4_K_M; an explicit model path selects each other row:

```sh
for file in SmolLM2-135M-Instruct-f16.gguf \
            Qwen2.5-1.5B-Instruct-f16.gguf \
            Qwen2.5-1.5B-Instruct-Q8_0.gguf \
            Qwen2.5-1.5B-Instruct-Q4_0.gguf \
            Qwen2.5-1.5B-Instruct-Q4_K_M.gguf; do
  python3 bench/speed.py measure --binary build/neuron --model-file "$NEURON_MODELS_DIR/$file" \
    --step "$file neuron" --isa avx512 --threads 4 \
    --output "bench/runs/$file-neuron.json" --notes 'Record actual load and power.'
  python3 bench/speed.py measure --llama --model-file "$NEURON_MODELS_DIR/$file" \
    --step "$file llama.cpp" --threads 4 \
    --output "bench/runs/$file-llama.json" --notes 'Record actual load and power.'
done
```

TinyStories uses the original prompt-set harness:

```sh
python3 bench/harness.py run-neuron --binary build/neuron \
  --model-file "$NEURON_MODELS_DIR/stories15M.gguf" --threads 4 --isa auto \
  --output bench/runs/tinystories-neuron.json --notes 'Record actual load and power.'
python3 bench/harness.py run --model tinystories-15m \
  --output bench/runs/tinystories-llama.json --notes 'Record actual load and power.'
```

The llama.cpp command collects the original 1/4/8-thread baseline. The
README selects its four-thread row. For the original Neuron binary, use
the M5 final source mapping in [SPEED.md](SPEED.md). The current engine's
arithmetic kernels are unchanged in M7. `m7_table.py` derives the table
from committed records; it does not collect new measurements.

## Build and runtime contract

These are implementation settings, not measured performance claims. This
record also supplies provenance for version numbers, format IDs and
example command budgets in the README and blog.

- The project uses C++20 and CMake 3.20 or newer. Model-free Python tests
  require Python 3.8 or newer. Local builds use GCC 11.4.0 or Clang 14.0.0,
  CMake 3.22.1 and Python 3.10.12. Tests have no third-party dependency.
- Release is the default build. `NEURON_WERROR=ON` adds `-Werror`.
  `NEURON_SANITIZE=ON` enables ASan and UBSan. `NEURON_BUILD_TESTS` defaults
  to ON. `NEURON_AVX2`, `NEURON_AVX512` and `NEURON_NATIVE` are compatibility
  switches; SIMD kernels always have per-function targets.
- The checked GGUF variants are F32, F16, Q8_0, Q4_0, Q4_K and Q6_K.
  Llama and Qwen2 are the supported dense architectures. Qwen2.5 1.5B
  Instruct, SmolLM2 135M Instruct and TinyStories 15M are the local targets.
  Names identify model families or formats, not new measurements.
- Threads default to one, with 1..256 accepted. Auto dispatch tries
  AVX-512, AVX2, then scalar. Explicit VNNI is supported on the test laptop.
- The CLI context defaults to 2048, reply budget to 128. TinyStories
  declares training context 128; the original baseline overrides it.
  README raw examples use 32 tokens; the demo uses reply limit 16 and
  context 256. The public examples choose four threads and build with two
  jobs. These are configuration choices, not speed claims.
- Server defaults are IPv4 `127.0.0.1` and port 8080. Its API routes use
  `/v1`; a zero temperature and top-p one mean greedy decoding. It
  rejects context overflow and invalid JSON with HTTP 400 and unknown
  models with HTTP 404. [M6 checks](M6_CHECKS.md) retain that contract.
